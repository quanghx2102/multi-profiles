# Audit Register Machine-Readable Migration Plan

- Status: Proposed; migration not started
- Current source of truth: `docs/AUDIT_REGISTER.md`
- Target schema: [schema.json](schema.json)

## Decision

Do not perform a partial Markdown-to-YAML/JSON conversion in this task. The current 34-item register includes substantial narrative fields and uncommitted user changes. Converting some items while leaving Markdown authoritative would create two sources of truth and make status updates unsafe.

## Target state

```text
audit/
  schema.json
  items/AUD-001.yaml ... AUD-034.yaml
tools/audit-register/
  generate
docs/AUDIT_REGISTER.md       # GENERATED — DO NOT EDIT
```

The generator must sort by numeric ID, render every field without loss, produce stable whitespace/order, validate enums and references, and fail when `CONFIRMED`/`RESOLVED` lacks evidence references. CI/docs-check must compare regenerated bytes with the tracked Markdown.

## Atomic migration procedure

1. Approve YAML versus JSON and the generator runtime as `DEC-EVIDENCE-001` follow-up.
2. Create one machine-readable item for every existing audit, preserving all text and IDs.
3. Validate round-trip field/content parity against the Markdown register.
4. Add deterministic generator and synchronization test.
5. In one reviewed commit, mark Markdown generated and switch governance authority to `audit/items`.
6. Until that commit, do not create authoritative item files under `audit/items`.

`schema.json` is ready for review and tooling design but does not change the current authority.
